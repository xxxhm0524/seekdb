# 已得分 e860 主线的独立优化

做题人选择以 `e86045306f5940613bfcf4aa84b0ee4bf74c20f1` 为主线，将目标调整为正式原始指标 **E ≥ 4500**，并取消本轮提测和时间限制。本分支仅用于优化及核验，不覆盖原工程、Dot 工程或报名分支。已有正式结果仍属于 e860：MySQL 通过，E 为 3115.658047；本候选没有正式成绩。

## 改动和来源

- 对已精算的 TopK 赢家复用距离和缓存字段，只读取缺失的普通投影列。需要原始向量或另一查询距离时继续物化。
- 预留记录编码空间，在小端机器批量复制原始 float32；解码时直接填充最终向量。记录字节格式不变。ASCII 长度校验按 8 字节跳过普通字节，其余 UTF-8 校验保留。
- 已消费 SQL 字符串使用移动，避免重复复制。
- AVX2 整数点积将行符号移到查询，使用行绝对值。编码范围仍是 [-127,127]，每个有符号 16 位配对和不超过 32258；没有减少编码精度。整数分数、证书、binary64 精算和主键并列顺序不变。AVX512 VNNI 路径保留。
- 缓存行仅保留已用普通字段前缀，维持原列位置；完整物化时补回列槽。
- 借鉴 [Freaybru 已报告得分版本的提交前缀映射](https://github.com/Freaybru/seekdb-2026/tree/3dfd062502aed05de32b269c64bd32995b0ffb5e)，增加最多 64 MiB、且不超过 RLIMIT_AS 四分之一的可选只读映射。映射失败或超限继续使用原位置读取。映射对象持有独立寿命，索引可以直接读取已提交的向量字节，省去一份全量 float32 副本。
- 完整精算回退可以在缓存预算内恢复原批量布局；预算不足时保留有界的映射扫描。写入、事务和压缩仍遵循原有根发布、回滚与同步顺序。新增映射只是读取路径。

参考作者报告的 4427.302903 属于固定提交 `3dfd062502aed05de32b269c64bd32995b0ffb5e`，没有将其后续分支 tip 的改动当成已得分代码。未复制参考作者的学习材料。e860 原有的 juanzhi 参考来源仍保留在原有文档和源码中。

## 已取得的证据

均在已授权的 A6000 原生 Linux 环境完成，没有运行 Docker。

- 未修改的 f4d 官方驱动与原断言：20/20。默认无参数入口，独立可写 `/data`、只读根目录、断网、UID 65534、2 CPU/2 GiB、无 swap。
- 26 组原有原生回归全部通过，包括协议、布局、事务、真实强杀、精确提交边界、压缩和恢复故障检查。故障注入使用动态构建，确保 LD_PRELOAD 实际生效。
- 与原始 e860 的 7862 项严格对拍通过。
- 映射探针核实实际映射/释放、写入/截断/替换失效、ENOMEM 回退、地址空间及尺寸预算。
- 216 项映射源精确比较通过，覆盖没有 Storage/文件描述符后的寿命、原子文件替换、不对齐向量、Unicode/NUL 变长字段、原始 float32 和 double 距离位、主键并列、1 MiB 预算下拒绝复制的精确回退。
- AVX2 修改通过 46260 次保守界/整数分数核对、1085 次检索逐位对比，包含近等距回退；正常 200 查询只精算 2650 行。

新旧版本在 16 组写入配对中生成相同数据库字节。映射源版本与前一组合版本的计量文件清单一致。历史报告继续保留其原来的源码版本，不据此宣称已经验证本候选。

## 分步测量与限制

这些是同机固定输入、配对顺序轮换的原生测量，不能相乘推算正式 E。

| 独立比较 | 观察结果 |
| --- | --- |
| 仅写入编码/ASCII，4 种形状各 4 轮 | 写入中位加速约 5.7%—7.6%，数据库逐字节相同 |
| 第一组合版本相对 e860 | 带普通字段投影查询中位加速约 23.4%—24.7%；纯 ID/距离约 1.1%—1.5% |
| AVX2 点积相对前一组合，6 轮 | 纯 ID/距离查询中位加速约 8.1%—9.6%；仅说明本机 AVX2 路径 |
| 映射源相对保留 float32 副本的版本，3 轮 | 含页缓存的内存采样峰值减少约 5 MiB；纯 ID/距离查询约慢 0.05%—0.34%，带普通投影约快 0.6%—1.4% |

内存由每个样本独立 cgroup 的 `memory.current` 每约 2 ms 采样，包含文件页缓存，但它是真实峰值的下界，不能写成 `memory.peak`。本机内核没有该接口。原始 io.stat 保留，不冒充平台指定设备的正式 B。编译器为 GCC 11.4，与平台 Dockerfile 的 GCC 13.5 不同。

与另一参考候选严格对拍曾报告 35 处差异，原件没有删除：原始 e860 也有相同差异。30 项是不同十进制文本能还原为相同 float32 位，5 项是未显式指定别名时的列名大小写；没有修改数据库去迎合这份比较器的文本格式假设。与 e860 本身的严格比较没有这些差异。

后续原生 CI、sanitizer、容量及最终提交身份应另外绑定。公开用例和有限对拍不能证明所有隐藏输入，也不能确认 E 达到目标。正式提测已由做题人取消，跨日不会自动恢复授权。
