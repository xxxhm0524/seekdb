使用 [juanzhi-gcb/seekdb 的 dfee55b8](https://github.com/juanzhi-gcb/seekdb/tree/dfee55b84284f4c39d2df45951cdbcb1d1baf1a2)。作者[公开材料](https://github.com/juanzhi-gcb/seekdb/blob/42f69e8320dcd8c802614f10cfb0699aa7551d2c/agent/conversation.json)的 `/experiments/43/output` 记录该版本正式 MySQL 通过、Agent Prompt 原始分 6.5 有效。这是作者公开的平台反馈记录，没有通过对方账户独立认证，也不属于本项目的成绩。

本项目固定该 commit，核验 39 个源文件的 SHA256，独立编译成对照程序。跨 3 张表执行 1600 步操作、1629 次请求，并以 Python 状态模型核对结果。CRUD、多行插入失败、BIGINT 极值、Unicode、向量查询、列别名、提交、回滚、重启及强杀一致。

最初对拍发现反斜杠转义约定不同：对方保留反斜杠，本实现支持 MySQL 风格转义。题包没有定义该项方言选择，原始差异记录为 `dialect-backslash-observation.json`；公共对拍使用语义明确的单引号字符串，另保留本项目的转义回归。未将对方的所有行为无条件视为标准。

对照源码只在测试阶段下载并编译，没有并入数据库核心，也没有复制对方学习材料。

## 明确的运行边界

* 允许一个显式事务；回收只在事务之间触发。长事务的未提交尾部仍需要磁盘空间。
* 回收需要同时保存旧文件和完整新文件，暂时需要额外磁盘空间；回收成本属于数据库进程的资源开销。
* catalog、单条 SQL 和单条记录需能单独装入内存，总数据量可以超过内存。
* 超出向量缓存预算时采用精确磁盘检索，保持正确性；延迟取决于实际数据量和存储性能。
* 以上检查不等于平台保留的正式用例已通过，也不能证明不存在所有未知缺陷。正式成绩仍待用户允许后验证。
