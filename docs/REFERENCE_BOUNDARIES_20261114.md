# 通过版本的边界差分审查

本文是 `65aa862` 核心的历史边界审查。后续全题复核又发现并修复深层 JSON 和操作符词法类型缺口；当前结论、54 份回归报告及 20 个 MySQL 逐用例结果见[全题要求复核](ALL_REQUIREMENTS_20261114.md)。历史 439 次对拍不构成完整协议证明。

本轮由用户要求检查“参考代码可以完成，而本版会失败”的输入，并要求逐条核对协议。正式提测仍然暂缓。本轮使用实际 Linux 数据库进程，不把旧解析器的一致性当成规范正确性的依据。

## 对照与证据

固定对照为 [juanzhi-gcb/seekdb 的 dfee55b8](https://github.com/juanzhi-gcb/seekdb/tree/dfee55b84284f4c39d2df45951cdbcb1d1baf1a2)，资格来自作者公开的正式通过记录，无法通过对方账户独立认证。39 个源文件按固定哈希下载。专门差分使用相同 GCC 13.5 构建两个程序。

被审查的前一冻结版是 `2b96adab6659952701b876a4468e4011ac05793f`。修复核心是 `65aa862d82b30bc9db61a14a8865ee397914ec2b`。完整原始响应、请求轨迹和提交/CI/报告哈希在 `validation/edge-review-20261114/` 及本地 CI 附件中保留。

* [完整回归](https://github.com/xxxhm0524/seekdb/actions/runs/43598504397)：47 份报告通过，包含官方 20/20、ASan/UBSan、协议矩阵、实际 2 GiB/2.62 GB 数据与恢复故障注入。
* [同编译器完整进程差分](https://github.com/xxxhm0524/seekdb/actions/runs/43598504346)：修复版 439 次观察没有“对照成功、本版失败”或独立真值失败。同一次运行还重建并重放旧冻结版，确认扫描器仍能检出 81 处失败观察。
* [修复前响应字节失败](https://github.com/xxxhm0524/seekdb/actions/runs/43597854434)：参考端可在上限内返回，而修复前版本超限。

81 是同一根因在有/无索引、带/不带引号等组合中的观察次数，不是 81 个独立缺陷。初版扫描器曾把 DDL/TX 可选的 `affected_rows:0` 差异也计入；后续按协议规范化，并使用同一旧二进制重新取得上述 81 的计数。

## 确认并修复的五类缺口

| 类别 | 最小或代表输入 | 修复前 | 修复后 |
| --- | --- | --- | --- |
| 不透明 JSON 编号 | `id=18446744073709551617`，或包含大整数的对象/数组编号 | 变成浮点、失去数值/类型；更大整数导致拒绝整帧 | 借鉴通过版的原始合法 JSON 值回传，覆盖成功、错误、COMMIT、shutdown 和暂存响应 |
| SQL 向量数值语法 | `[+1,.5,1.]`、`[001.25,0,0]`、SQL 空白/注释 | 用 JSON 数字语法拒绝参考端支持的 SQL 写法 | SQL 绑定按对应数字语法解析；逗号、维度、有限 float32 与完整输入仍检查 |
| 非负整数的符号 | `LIMIT +1`、`LIMIT -0`、`VECTOR(+3)` | 直接调用无符号转换而拒绝合法符号 | 接受前导正号和负零；负的非零数、非法尺寸和越界仍拒绝 |
| ORDER BY 作用域 | `SELECT id,id FROM t ORDER BY id` | 把普通重复投影标签当成多个显式别名而报歧义 | 仅显式 AS 进入别名命名空间；真正重复的显式别名仍报错 |
| 响应字节上限 | 10000 行 × 128 维向量投影 | float32 先提升成 double JSON 节点，文本过长 | 按 float32 最短往返文本输出，距离仍按 double 输出 |

向量语法补齐没有恢复旧的数字拼接漏洞。`[1 2,0,0]`、`[1/**/2,0,0]`、字符串/布尔/NaN/Infinity 元素、缺逗号、维度错误、尾部垃圾和原始 NUL 仍拒绝。新增 157 项生产路径检查覆盖 22 种数字拼写、float32 位模式、晚期失败回退及重启。

编号的修复依据是协议的“原样回传，包括 JSON 类型”，不是把编号改成字符串。解析器直接改编自固定通过版 `src/protocol/jsonl.hpp`，原文件 SHA256 为 `f9d04476c94e565a2e8efff6845b9c869ac02e351d04a4ab40e564f18ca18f23`。原始值跨度只能在整帧验证完成后用于响应，并在响应结束前保持原输入存活。旧 RapidJSON/有界数字 DOM 路径已从生产代码移除。

## 字节上限和精度

判题器 `max_response_bytes` 是 16777216 字节。实际完整报文测量如下：

| 程序 | 响应字节 | 门限 | 128 万个 float32 分量 |
| --- | ---: | --- | --- |
| 修复前 | 25393654 | 超限 | 位模式往返正确 |
| 固定通过参照 | 14330893 | 通过 | 位模式往返正确 |
| 修复后 | 14330893 | 通过 | 位模式往返正确 |

没有删行、降低向量计算精度或改用近似结果。向量投影比较采用 JSON 解码后再转 float32 的位模式，保留有符号零；BIGINT 与文本继续精确比较，double 距离检查保持原容差。这避免把“某一种 double 小数文本”误当成 float32 数据正确性的唯一表示。

## 性能与范围

[协议修复后的三方三轮比较](https://github.com/xxxhm0524/seekdb/actions/runs/43599992446) 中，短正文写入/查询为 0.4066/0.3759 秒，参照为 0.3779/0.3685 秒；1 KiB 正文为 0.5414/0.3776 秒，参照为 0.5591/0.4435 秒。没有宣称全面领先，也没有由文件大小或观察到的 io.stat 推算赛事 E、排名或分数。

这些是有限的可复现测试，不是所有合法输入的数学证明。九个保留的正式输入不可见，真实准入与成绩仍须平台评测。当前没有使用正式提测机会。协议中的 SQL NULL 表示约定在本赛题不要求实现的 SQL NULL 语法上不适用；`id:null` 已验证。恢复证明针对进程强杀与存活内核，不扩展为机器断电证明。
