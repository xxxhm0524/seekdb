## 找到的问题

冻结版 `977fb6d6e4f7dc2865ab5ba847ae3c489ba27100` 已通过功能回归，但缓存仍保存整行。10000 行、128 维时，正文从 16 字节增至 1024 字节会撑满 16 MiB 缓存，查询回退到磁盘路径。独立读取探针复现 20 次查询读取 133027228 字节；参考实现的工作列缓存避免了无关正文的影响。

同时，原距离循环逐条执行标量运算，未能有效利用同类查询的批量计算。数字绑定使用通用 JSON 数组对象，也产生可测量的解析开销。

## 改动及正确性约束

* 向量缓存保存向量、主键、过滤和排序所需列。最终投影未缓存的内容按赢家记录位置读取；列集合变化时合并需求，缓存拒绝按列集合记录，避免大字段拒绝影响后续小字段查询。
* 保持 16 MiB 预算；物化前检查预算，不为了缓存读取无关大字段。
* float32 向量按 8 候选分块排列；每个候选仍按原维度顺序以 double 累加。低维使用精确 KD 下界，高维使用精确分块平面索引。根据 CPU 能力选择 scalar、AVX2 或 AVX-512，提供无对应指令时的回退。
* 不使用降精度、近似距离或 FMA 收缩。生产编译器下三种可用内核完成 4608 次逐位比对；极端 float32 与磁盘路径的查询回归继续通过。
* 使用严格数字词法和 `from_chars` 直接绑定向量，保留有限 float32 临界舍入、double 下溢回退、维度和完整输入检查。17246 个解析兼容/边界样本通过。
* 新测试发现旧 JSON 库会把原始 NUL 当结束符并忽略尾部。现在向量文字和 JSONL 帧都要求完整输入，原始 NUL 帧拒绝执行，JSON 转义后的 VARCHAR NUL 数据仍可读写。

提交持久化、磁盘格式、事务和恢复实现保持原语义。

## 同机三方三轮结果

每轮使用相同数据、输入和独立真值。输入及真值生成在计时外，角色顺序轮换；统计三轮中位数。10000 行 × 128 维、1000 次 TopK10，一半为普通列等值过滤。

| 正文字节/行 | 原冻结版写入秒 | 新版写入秒 | 对照写入秒 | 原冻结版查询秒 | 新版查询秒 | 对照查询秒 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 16 | 0.7094 | 0.4827 | 0.2332 | 1.7874 | 0.5805 | 0.2580 |
| 1024 | 0.8928 | 0.6684 | 0.3656 | 14.6414 | 0.5625 | 0.3162 |

同一轮三方比较中，新版查询耗时为原冻结版的约 32.5% / 3.84%，写入为约 68.1% / 74.9%。峰值内存也降低。新版仍慢于对照，查询约为其 2.25 / 1.78 倍，不能由这些结果承诺排名。
