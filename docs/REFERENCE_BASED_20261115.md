本报告保留原 c2/4da 阶段的实测归属。后续 Prompt 编排及读取故障注入兼容修复分别见 PROMPT_RECORD_REVIEW_20261115.md、CI_READ_INJECTION_20261115.md；旧“未推送/未跑 GitHub CI”的描述对应报告当时的快照，不作为新提交状态。

用户决定废弃先前独立实现，直接在已得分的公开参考基础上优化。本工程从 [juanzhi-gcb/seekdb 的 a08e66e](https://github.com/juanzhi-gcb/seekdb/tree/a08e66e299847ca539c419cfbc67593357246627) 独立检出；其 src/include/tests/CMakeLists/Dockerfile 与作者公开反馈指向的 a24d2cd 运行核心逐项匹配。作者自述的 MySQL 通过和性能结果属于对方，本候选没有平台成绩，也没有独立登录验证对方账户。

原工程和 Dot/Codex 独立候选仅作归档；本工程的运行代码没有从其协议、WAL、pager 或 SQL 引擎迁入。复用的 Python 内容属于外部测试工具和独立预期，不进入数据库程序。

## 保留的唯一运行改动

运行核心为 `c2c2b42f6782549049b14764c7a105389cb5289f`。相对参考只修改 src/sql/binder.cpp、src/types/value.cpp，并新增 src/types/float32.hpp：带引号的普通数字向量直接形成最终 float32 缓冲，减少原先临时 double 数组及第二次遍历。公用单分量转换保留原 binary64 → binary32 舍入、最大有限值区间、溢出判断和负零。

完整语法必须先接受，再按原优先级报告 binary64 数字错误、维度错误和 float32 范围错误；含注释等复杂文字仍使用原有词法路径。没有改变协议、SQL 范围、索引、缓存答案策略、持久格式或提交确认顺序，没有修改算术精度、召回要求或 fsync。

## 实测收益与限制

在 A6000 主机的 AMD EPYC 7282 / GCC 11.4 原生环境对照同源基线。实际 JSONL 程序默认启动，私有挂载与网络命名空间，UID 65534、根只读、独立 /data 可写、2 CPU / 2 GiB / swap=0。测试时只给本次进程设置 CPU 亲和性，不修改全局或其他用户任务。

大维度合法查询使用空表上的 L2_DISTANCE 投影及 LIMIT 0：执行器仍必须完整绑定和校验向量，输出为空。每组四轮、交替版本顺序，记录实际数据库进程的 VmHWM，包含启动及解析，排除客户端 Python。这是解析工作负载，不冒充正式 M、全库容量或标准 128 维速度收益。

| 维度 | 原版 VmHWM 中位数 KiB | 候选 KiB | 降低 |
| --- | ---: | ---: | ---: |
| 131072 | 5268 | 4212 | 20.0% |
| 1048576 | 21314 | 13130 | 38.4% |
| 4194304 | 76564 | 43828 | 42.8% |

标准负载为 10000 行 × 128 维、1000 个 TopK10 请求，10 次预热；BIGINT/VARCHAR 过滤各自包含一半无过滤查询，并分别测有/无索引。六轮共 48 个样本、48000 次计时查询，使用相同固定输入和独立标量全排序 oracle；每条结果及每个样本强杀重启后的结果都验证。计时包含真实 JSONL 请求往返，排除造数、oracle、预热和答案核对。

四组配对周期加速比中位数为 1.005、1.002、1.003、0.982，未显示一致速度提升，其中 VARCHAR/有索引组约慢 1.8%。因此本候选只主张上述大维度解析内存下降，不主张标准负载更快、正式分数提升或普遍加速。每轮异常和原始值保留，没有删掉慢样本。

另外三项尝试没有保留：跨单元编译优化（24 个样本）、关闭整数界筛选（16 个样本）、关闭保守界筛选（16 个样本），均无一致收益或出现退步。各实验仅在自身同条件配对组内比较，未混用不同 CPU 亲和性下的绝对耗时。

## 实际验收

- 参考原版 70/70 项 CTest 与官方 20/20；候选亦为 70/70 和官方 20/20。官方驱动及断言未修改。
- 7862 次扩展边界对拍通过，保留双方真实响应并含独立数值/排序预期；新增的大编号报文上限用例通过。
- 6175 个快/慢向量绑定比较核对逐位值、错误码和错误文字，包含新增的错误优先级交叉组合。
- ASan、UBSan、Leak 检查通过官方公开用例、7862 次对拍、大编号边界、向量文字与数值极值/并列测试。诊断构建与发布构建分开记录。

- 附带原生验收器在新临时工作区实际重放成功；该次复用已编译的同源程序，并明确记录 existing_build_reused=true，不冒充重新编译。

38 个运行输入同时记录原始 Git 字节及 LF 归一哈希；原 CMakeLists.txt 中有一处已提交 CRLF，保留原字节，没有改全局 Git 设置。早期测试工具的临时目录和复制权限校准失败记录保留，不算作程序通过或程序缺陷。

## 复现与发布

在已授权且具备 root、挂载/网络命名空间和可写 cgroup v2 的 Linux 上：

```sh
python3 tools/native/verify.py
python3 tools/native/verify.py --benchmark
python3 scripts/check-reference-candidate.py
```
