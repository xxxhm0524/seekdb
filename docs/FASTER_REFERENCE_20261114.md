# 借鉴通过版本后的进一步优化

本文是前一版本的历史快照。后续边界审查发现这里的通过记录没有覆盖任意精度编号等协议边界，现行结论见 [边界差分审查](REFERENCE_BOUNDARIES_20261114.md) 和 [协议验收矩阵](PROTOCOL_TRACEABILITY_20261114.md)。

本轮按用户要求，继续借鉴已公开记录通过的实现并追求更快的执行速度。正式提测仍然暂缓，本文的测试不消耗正式提测机会，也不能证明平台已经给分。

## 参照与改写范围

固定参照仍是 [juanzhi-gcb/seekdb 的 dfee55b84284f4c39d2df45951cdbcb1d1baf1a2](https://github.com/juanzhi-gcb/seekdb/tree/dfee55b84284f4c39d2df45951cdbcb1d1baf1a2)。资格证据及其作者发布记录的局限见 [上一轮审查](SCORED_REFERENCE_REVIEW_20261114.md)。该版本的源码按 39 个文件哈希固定，不随对方分支变化。

借鉴的具体设计来自其 [typed_scan_cache.hpp](https://github.com/juanzhi-gcb/seekdb/blob/dfee55b84284f4c39d2df45951cdbcb1d1baf1a2/src/sql/typed_scan_cache.hpp)、[certified_candidates.hpp](https://github.com/juanzhi-gcb/seekdb/blob/dfee55b84284f4c39d2df45951cdbcb1d1baf1a2/src/vector/certified_candidates.hpp) 和 [int8_bound.hpp](https://github.com/juanzhi-gcb/seekdb/blob/dfee55b84284f4c39d2df45951cdbcb1d1baf1a2/src/vector/int8_bound.hpp)。本实现重新编写接口和实现，接入已有的不可变表根、行位置、缓存预算和错误处理，没有把对方数据库作为运行依赖，也没有复制其学习材料。

* 按普通过滤列物理聚集缓存行，使用二分得到等值和范围区间；其余条件继续逐行校验。行位置和主键随向量一起置换，返回时仍按精确距离和主键排序。
* 精确平面内核从每块 8 候选改为 32 候选，提高独立累加链的并行度。每个候选仍按维度顺序以 binary64 累加。
* 直接沿用 `TypedScanCache::finish` 的布局选择：证书路径的原始向量保持行式连续，减少少量候选精算读取的缓存行。准备期只需一块向量暂存，纳入预算。遇到完整扫描时一次性恢复分块布局，此后继续使用原来的精确批量内核，避免每条查询重排全表。
* 附加有界 int8 编码筛选。编码原始 float32 向量仍保留，每次只在可证明其他记录都更差时接受候选集合，否则执行完整精确路径。
* 写入最多聚合 64 KiB 记录字节、1024 个位置条目，减少逐行系统调用；大记录直接追加。B+ 树仍负责重复主键检查，失败仍回退整个 SQL 语句。
* B+ 树查找直接二分页中的键；未分裂的插入只修改当前语句拥有的页。已拥有子页的地址不变时，父页无需重新解码和保存。页布局、校验和写时复制归属保持不变。
* 投影复用已计算的相同查询距离；只有需要向量本体或另一查询距离时才物化向量。内存响应不再无条件尝试删除并未创建的暂存文件。
* 使用与参照相同的进程崩溃模型：所有记录、catalog、树页写完，提交根写完，再统一同步文件后确认提交。一次同步不能建立机器断电时的前置写入排序保证。本次精确中断覆盖根发布前后、同步前后；确认成功的事务始终等待同步成功。
* Linux CPU 剖析定位了逐字符文本复制。SQL 引号中的普通字节改为有界整段复制，转义保留原规则；请求层引入通用 RapidJSON，来源为 [固定提交](https://github.com/Tencent/rapidjson/tree/297637bc0a0f00dc504dbc1a47ebdaa577f8ae19)。39 个头文件/许可证按哈希固定，许可证进入运行镜像；不承担数据库核心。
* 请求整帧原始 UTF-8 先校验，RapidJSON 严格解码转义，逐层检查重复键。SSE2 扫描使用额外 32 字节自有填充；普通整数精确转换，浮点或超 64 位数字回到原严格解析器。48279 个样本对拍核对接受性和完整值，实际大 SQL 帧还确认使用了新路径。

## 整数筛选的正确性边界

每个坐标编码为 `c ∈ [-127,127]`，公共正尺度为 `s`，保存完整 float32 源坐标。对每条记录在构建时计算并向外舍入 `||x-sc||₂` 的上界，保留最大上界 `Ex`；每个查询同样计算 `Eq`。三角不等式给出 `||x-q||₂ ≥ s||cx-cq||₂-Ex-Eq`。平方、加法、开平方、尺度乘法和减法的边界都按保守方向保护；clamp 造成的误差计入上界。

整数点积和范数以 int32 精确计算，维度限制为 32–4096，中间值在 int32 范围内。AVX2 把无符号编码拆成低 7 位和最高位，分别计算相邻乘积后再拓宽到 int32，避免 `maddubs` 的 int16 饱和。支持的 CPU 可使用无饱和的 VNNI；所有可用内核与便携整数循环比较。

候选堆保留最小的 32 个编码分数，仅为 K≤16 的查询尝试证书。整个扫描中堆阈值只能下降，因此最终阈值不大于任何被排除记录的编码分数。候选集合内全部使用原来的按维度顺序 double 距离；只有排除集合的距离下界严格大于第 K 个结果的保守上界时，才接受结果。上界还覆盖原 double 累加和 sqrt 舍入，严格大于比较保留距离并列的主键顺序。

与对照的 `certified_candidates` 相同，按编码分数依次精算候选；下一候选的保守界同时覆盖剩余候选和所有被排除记录，证书成立后提前结束。原先固定精算全部 32 条的路径先被新增断言检出，再完成优化。本地 200 条固定查询的精算量由 6400 降为 2650，最终仍与完整精算逐位一致；最终 Linux 数值见交付报告。

浮点环境必须为 RN、渐进下溢且异常屏蔽；只检查环境，不修改进程状态。不满足环境、预算、维度、K、行数或证书条件时走完整精算。近等距、极端数值、查询超出编码范围和不足 K 条均有覆盖。整数编码不用于返回距离，不改变 float32 源值，也不靠允许的 Recall 损失提速。

## 验证与测量

本轮核心为 `ac217b1875cc7382c345b24ddf7dea23a384fe0c`。[完整回归](https://github.com/xxxhm0524/seekdb/actions/runs/43592647314) 的 37 份报告逐份检查通过，sanitizer 日志没有发现 ASan、LeakSanitizer 或 UBSan 错误。另有 4 份专题报告，来源提交、CI URL 和报告 SHA256 在 `validation/faster-review-20261114/provenance.json`。其中旧数值内核报告对应的相关源码已逐字节核对保持一致。

[最终三方比较](https://github.com/xxxhm0524/seekdb/actions/runs/43592647300) 使用冻结的 bcd4a3f 前一版、当前候选和固定通过参照，三轮中位数如下，单位为秒：

| 1024 | 0.6580 | 0.3413 | 0.3665 | 0.5670 | 0.2643 | 0.3110 |

1 KiB 正文场景，本版写入耗时约减少 6.9%，查询减少 15.0%；三轮查询耗时比分别为 0.8682、0.8190、0.8417。短正文仍分别慢约 4.0% 和 3.1%，不能宣称全面更快。相对前一冻结版，两种正文场景的写入均约减半，查询耗时约为原先的 46%。

内存与文件占用仍有差距。文件字节不等于物理 I/O B，没有据此推算赛事 E 或排名。数据返回的 ID 与独立真值一致，写入后的记录和重启持久性检查通过。对照的原始生产配置是 Alpine/GCC 14；本实验统一到 GCC 13.5/Ubuntu，用于比较实现，不能声称复现对方正式平台成绩。

生产编译器下的整数证书探针完成 61680 次界/整数内核核对、1085 次检索对拍。200 条固定查询实际精算 2650 条候选，200 次均覆盖行式源布局；完整扫描触发的一次性布局恢复也被直接记录。原有精确距离内核的 18432 次逐位核对、17246 个向量文字样本，以及请求解析器的 48279 个样本均通过。学习材料为 72917 字节，根目录与 agent 副本一致，正式提测未执行。

新增验证覆盖聚集后的所有普通比较、Unicode/NUL、混合列与矛盾范围、赢家完整投影、回滚、重启；整数 SIMD、保守界、完整精算逐位对比及强制近等距回退；64 KiB 前后和大记录混合写入、超 1024 条元数据、多个批次后的晚期重复键/非法向量、失败后文件字节不变及同一事务此前成功语句可提交。

其中一次生产容器测试因宿主机无权读取 mode-0600 文件而失败，后续响应故障步骤因前置二进制未提取也未执行；这两项不能视作通过。测试已改为由文件所属容器用户计算哈希，生产权限和数据库源码没有因此放宽或改动。失败原件保留，最终完整重跑后再确认通过。

受控比较仍为 10000 行 × 128 维、1000 条 TopK10、一半等值过滤、16/1024 字节正文；三方同机三轮、执行顺序轮换。输入和真值在计时外，查询返回的 ID、距离、正文、数量及重启持久性另外核对。编译器、运行库、2 CPU/2 GiB、禁用 swap、只读根及运行期断网一致。数据文件大小和观察到的 io.stat 不冒充官方专用设备 B；不由本地结果换算 E、排名或赛事分。
