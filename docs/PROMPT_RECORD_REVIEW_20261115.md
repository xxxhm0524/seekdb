# Prompt 记录的真实贡献编排

用户先选择采用补充真实历史草稿，再要求突出做题人的主导作用，并要求修改前说明写法。已先给出“用户确定目标与验收—用户质疑并调整路线—Agent 实现与实测”的方案；本次按该方案整理。

入口从原先6条用户指令扩展为18条真实用户记录，包含最初 goal、大整数编号的具体质疑、MySQL 准入要求、参考对照要求和弃用旧实现的路线决定。原话及角色保持不变；新增的材料摘要、主导过程概述和证据链索引标为 Agent 整理，放在报告前部，便于先看到问题和决策，再读取结果。

突出的是已有贡献：做题人设定目标与优先级、质疑反复修补的结果、要求逐协议审查和独立对照，并明确改变实现基础。具体代码、优化设计和实验由 Agent 或参考作者完成时继续保留来源，不改写成用户个人设计或操作。

特别区分：用户消息中的大整数缺陷段落是用户引用 Agent 报告；用户自己的贡献是随后提出质疑并要求逐项核对。材料没有写成“用户首先发现并亲自修复该错误”。早期独立实现与后来的参考衍生候选分阶段记录，不把不同源码的结果并为一次修复。

三个候选问题链只供定位原话与结果，是否有效、是否应合并及怎样评分由评审判断，不自报得分。实际报告以原字符串放入同一 JSON，并保留来源摘要；引用均定位到字符串且使用精确片段。原材料和经用户选择的草稿均保存原字节，生成器可重复生成，检查器确认用户原文没有被修改。

这份整理不制造未发生的技术理解，也不承诺消除平台的 Prompt 合并无效提示。今天旧版本 e860453 的正式结果与本候选分开，当前材料尚无对应正式评价。
